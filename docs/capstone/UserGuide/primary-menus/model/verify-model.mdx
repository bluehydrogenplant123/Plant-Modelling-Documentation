# Verify or Unverify Model

Use this control to move a saved, normal root diagram between **Unverified** and **Verified**. Verification continues to protect workflows that already depend on the verified state; unverifying returns the root diagram to its editable state.

## Where To Find It

1. Open an existing diagram.
2. Select the **Model** primary menu.
3. Read the current state on the switch-like button: **Unverified** or **Verified**. Click it to request the opposite state.

## What It Does

The button text reports the diagram's current persisted state. Clicking it requests the opposite state:

- **Unverified** means the diagram is editable; clicking requests `isVerified: true`.
- **Verified** means the diagram is protected by the existing verified-state guards; clicking requests `isVerified: false`.

The switch label, `aria-checked` value, and application state change only after the server returns the canonical saved state. Repeating the same desired state is safe and does not create an error.

## Basic Steps

1. Confirm that the root diagram is saved and that no existing guard disables the control.
2. Click the action matching the change you want.
3. Wait for the success message and the button label to switch.

## Result

The server stores the selected verification state for the owner diagram. The control is not shown for subnetwork blueprint/instance diagrams. A normal root diagram can still be verified before entering Multi-TP, so the existing verified-then-Multi-TP flow is preserved.

If the request fails, the displayed verification state is not changed. An unexpected change after a failure should be treated as an error and reported with the diagram ID.
