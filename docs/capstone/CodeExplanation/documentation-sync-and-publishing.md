## Overview

The `docs/` directory in HYPRONET-GUI is the source of truth for the current online documentation. A GitHub Actions workflow copies that directory into the separate `Plant-Modelling-Documentation` repository, generates navigation from the copied directory structure, and pushes the synchronized result to the target repository's `main` branch.

The sync workflow does not hardcode the names of documentation sections. Every non-empty top-level directory under `docs/` can become a top-level section on the published site.

## Source Files and Repositories

- `.github/workflows/sync-version6.1-docs-to-documentation-repo.yml`: source checkout, target checkout, documentation synchronization, dynamic navigation generation, and target commit.
- `docs/`: authoritative source pages and assets maintained with the application code.
- `docs/**/_category_.json`: optional source metadata for section labels and ordering.
- `bluehydrogenplant123/Plant-Modelling-Documentation`: target Docusaurus repository; synchronized content is written under `docs/capstone` and `static/capstone-assets`.
- `Plant-Modelling-Documentation/docusaurus.config.ts`: target-site URL, base URL, repository metadata, and Docusaurus build settings adapted by the sync.

## Purpose and Responsibility

The workflow owns synchronization and generated navigation. It keeps the public documentation aligned with the default branch without requiring contributors to edit a second copy of every page.

The target repository owns the Docusaurus application and its GitHub Pages deployment. The source workflow pushes content to that repository; it does not itself run the target site's Pages deployment.

## Triggers and Inputs

| Input | Source | Effect |
| --- | --- | --- |
| Changes under `docs/**` | Push to HYPRONET-GUI | Starts the workflow when the push is on the repository's current default branch. |
| Workflow-file change | Push to HYPRONET-GUI | Runs the updated synchronization logic on the default branch. |
| `workflow_dispatch` | GitHub Actions | Allows a manual synchronization run. |
| `DOCS_SYNC_TOKEN` | Repository secret | Grants read/write access to the target repository. |
| Top-level source directories | `docs/` | Define the set of generated documentation sections. |
| `_category_.json` | Optional source file | Supplies a section label and position; otherwise the directory name is humanized. |

The job-level condition checks `github.ref_name == github.event.repository.default_branch`. A documentation commit on another branch can be reviewed without publishing it.

## Synchronization Flow

1. The workflow verifies that `DOCS_SYNC_TOKEN` is available.
2. It checks out HYPRONET-GUI into `source/` and `Plant-Modelling-Documentation/main` into `target/`.
3. For every top-level directory under `source/docs`, it mirrors files into `target/docs/capstone/<section>` and `target/static/capstone-assets/<section>`.
4. It removes synchronized target sections that no longer exist in the source.
5. If `docs/` contains top-level files, it copies them into a generated `Source Root` section and exposes non-document files as downloads.
6. A Node script scans every copied `.md` and `.mdx` page, reads optional category metadata, and computes a normalized section slug.
7. The script rejects duplicate generated slugs.
8. It writes generated-index metadata for each non-empty section, replaces `sidebars.ts` with an autogenerated sidebar, and creates the documentation homepage cards from the discovered sections.
9. The workflow commits all synchronized target changes with the source branch and source SHA in the commit message.
10. It pushes the commit to `Plant-Modelling-Documentation/main`, where the target repository's deployment process publishes the Docusaurus site.

## Generated Navigation Contract

| Generated item | Rule |
| --- | --- |
| Top-level sidebar | Uses `{type: 'autogenerated', dirName: 'capstone'}`. |
| Section label | Uses `_category_.json.label` when present; otherwise humanizes the directory name. |
| Section order | Uses `_category_.json.position` when it is numeric, then sorts by label. |
| Section route | Normalizes the directory name to a lowercase hyphenated slug. |
| Section landing page | Uses a Docusaurus `generated-index` at `/capstone/<section-slug>`. |
| Homepage card | Shows every non-empty discovered section and its current page count. |

Adding a new top-level documentation directory does not require a workflow edit. Add current `.md` or `.mdx` pages, and optionally add `_category_.json` for a controlled label and position.

## Side Effects

- `rsync --delete` makes each synchronized target section match its source section exactly.
- Target sections removed from `docs/` are removed from the synchronized documentation and asset trees.
- The workflow rewrites target `sidebars.ts`, the Capstone homepage, and generated section metadata on every synchronization that changes them.
- Direct edits under the target repository's synchronized `docs/capstone` or `static/capstone-assets` paths can be overwritten by the next source sync.
- A successful run can create a commit and push it to the target repository's `main` branch.

## Error Handling and Edge Cases

- A missing `DOCS_SYNC_TOKEN` fails before either repository is changed.
- The workflow exits on shell errors because synchronization uses `set -euo pipefail`.
- Two directory names that normalize to the same route slug fail the navigation step.
- Empty top-level directories are not included in generated navigation.
- If no files changed in the target checkout, the commit step exits without creating an empty commit.
- A source change outside `docs/**` and the workflow file does not trigger documentation synchronization.

## Extension Points

- Add a new section by adding a non-empty top-level directory under `docs/`; do not add its name to the workflow.
- Add or update `_category_.json` when a section needs an explicit label or position.
- Change generated homepage or sidebar behavior only in `.github/workflows/sync-version6.1-docs-to-documentation-repo.yml`; editing generated target files alone is not durable.
- If another source asset type needs special handling, update both the document copy and static-asset copy rules and test deletion behavior.

## Testing and Verification

Before publishing:

1. Run `git diff --check` in HYPRONET-GUI.
2. Confirm every new internal documentation link resolves to a source file.
3. Test the synchronized copy with the target repository's production Docusaurus build.
4. Add a temporary unlisted top-level directory during workflow testing and confirm it appears without a hardcoded workflow change; remove it before committing.

After publishing:

1. Confirm the target commit message contains the expected HYPRONET-GUI source SHA.
2. Confirm the target repository's Pages workflow succeeds.
3. Open the documentation homepage and every changed route.
4. Confirm new sections appear in both the homepage cards and sidebar.

## Known Cautions

- Update current source pages in HYPRONET-GUI. Changes made only to synchronized target copies are temporary.
- Deleting or renaming a source directory also removes or changes its public route after synchronization.
- Keep top-level directory slugs unique after normalization.
- Do not commit generated Docusaurus build output back into HYPRONET-GUI.
- The workflow filename retains `version6.1`, but its current synchronization source is the repository's `docs/` directory and its branch check uses the current default branch.
